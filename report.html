Lisa OS — state of the build

Snapshot generated 2026-08-06 · org Lisa-AgenticOS · latest OS release v20260805.81 · shell lisa-desktop-shell 50.4 pinned and published

The theme has changed. Yesterday it was the build is ahead of its own verification. Tonight the verification caught up and found that a lot of what was believed done was not — including two fixes shipped as correct the night before. Twenty-four findings came out of two adversarial reviews and a device sweep; sixteen are fixed, all four remaining HIGHs among them. Nothing below is claimed on the strength of a green test alone: every fix in this batch was mutated and watched go red first.

Lisa Desktop photographed itself first time

GNOME 50 gates org.gnome.Shell.Screenshot to the media-keys daemon and the portal, so we were locked out of our own compositor (#266). The fork now authorises a caller by /proc/<pid>/exe under /usr/lib/lisa/bin, root-owned and not group-writable — never a bus name, which anything on the seat can claim. 3840×2160, captured on the reference iMac's own GPU. Negative controls are what make it mean something: the same binary at /usr/bin/gdbus is refused, the same binary owned by lisa is refused, and the unpatched shell refuses even the authorised caller. A Lisa capture forces the flashspot whatever the argument says — measured, luminance 0.866 vs 0.628 — so no capture is invisible.

The desktop is confirmed ours, from the device rather than the packaging: DESKTOP_SESSION=lisa-desktop, session gnome-session --session=lisa, and no stock gnome-shell package installed at all. One asterisk: XDG_CURRENT_DESKTOP=GNOME, so every app that branches on that variable is told it is on GNOME (lisa-desktop#2).

7Standing risks worth naming

  • A green gate is not a working gate. Three vacuous tests were caught this week, plus two gates that passed when their subject was deleted. Every new gate now has to fail on absence, and mutation-by-deletion is part of the bar.
  • A mutation sweep that cannot compile scores perfectly. One sweep reported 25/25 killed while 15 mutations had been rejected by the compiler — a broken workspace is indistinguishable from a killed mutant. Sweeps run out-of-tree now.
  • Documentation that understates is the dangerous kind. Eight ADRs claimed less than the code did. That is what makes someone rebuild a thing that exists, or delete working code to match a doc.
  • An interpreter on an allowlist authorises everything it can run. The reason #289 and #306 are not fully closed.
  • Two repos still ship the same files. ADR-0057 settled ownership and conflicts= makes it loud, but ADR-0039 step 6 — the source migration — is untouched, and it is the seam that would duplicate lisa_ui the same way.
