Lisa OS — state of the build

Snapshot generated 2026-08-05 (updated: org-wide) · org Lisa-AgenticOS · latest OS release v20260804.77, next one building · 38 open issues across the org · this file is untracked, regenerate at will

One theme runs through everything below: the build is far ahead of its own verification. Roughly three days of finished, tested, mutation-checked work is stacked behind two gates — a green nightly (so a release can be cut) and a working session restart on the iMac (#267, so anything visual can be seen at all). Until those two open, most “done” work is done-but-unseen. That is why the next moves are sequencing, not feature choice.

Right now — nightly fully green, release build in flight building

The keyring blocker (#270) is fixed and proven: mkosi builds its keyring in its own sandbox; the fix seeds the [lisa] key there, and the image job is green.

The ab-sysupdate red was the harness, not the OS: a re-run against the same image artifact passed all five jobs. The guest’s network probe cannot detect a dead host server under QEMU user-net and the server is never verified host-side — filed as #272 so the next occurrence doesn’t cost a diagnosis round.

The release dispatch then failed to parse: the build step’s templated run block had outgrown GitHub’s 21,000-character expression cap (the #270 keyring work pushed it over — every dispatch since Aug 4 evening would have failed). Fixed in 564c9f0 by passing VER via env:. Release run 31012229114 is now building; it ships the keyring fix, lisa dev, the Mail redesign, and the Aug-4 shell fixes to the device.

⚠ Split-repo drift — two sources of truth for the shell are live

The Aug 2 split (ADR-0039) extracted shell/* and apps/* into lisa-desktop and lisa-apps, but no sync mechanism exists — development continued in the monorepo, and the split repos’ main branches have had no code since Aug 2. Meanwhile ADR-0039 step 4 made the image install lisa-desktop-shell from lisa-desktop’s package: the shell that boots is built from the older tree, while the monorepo’s shell fixes (dock badges parser, key bindings) ride its own packaging. Step 6 of the plan — remove the trees from the monorepo so one copy exists — is the real fix; until then, every shell change needs a deliberate answer to “which repo does the device get this from?”, or it quietly ships from neither.

6What to tackle next — in order

The ordering principle: drain the verification queue before adding to it. Every new feature landed now joins the same unseen pile. The fastest way to make three days of work real is one release and one session at the machine.

  1. Get the nightly green and cut the release.

    In flight. If the re-run passes, cut immediately; if it fails the same way, the harness gets a verified server-liveness check before anything else, because a gate that fails for its own reasons blocks everything.

  2. Fix #267 (Log Out does nothing).

    The keystone: it is the only way to restart the Shell on Wayland, and ~10 issues’ worth of finished work cannot be verified until a session can be restarted. Small surface, outsized leverage.

  3. One seated verification session at the iMac.

    Update to the new release, log into Lisa Desktop (first human ever), then burn the queue in one pass: #255 Super+Space, #263 dock, #262 Show Apps, mail rail/settings/Smart, Surfer tabs, splash, #191 on a fresh session, #19 unprivileged update. Each one closes or files honestly.

  4. Ship lisa dev (#130) through the channel.

    It already works; it just isn’t a product until the release installs it. Packaging + the shim lint gate closes the issue.

  5. Then choose one feature lane and stay in it.

    Recommendation: the agent-capability lane — #216 (make write tools reachable) then #157 (Assistant write-tier + memory). It is the thesis of the OS; Mail compose and Surfer passwords are worthy seconds.

RiskWhy it matters
Unpinned build inputs (#271, Arch base)A build that was green yesterday can go red with zero commits — every such failure costs a diagnosis day, as #270 nearly did.
Split-repo drift (section 4)The shell that boots is built from lisa-desktop’s Aug-2 tree while shell development continues in the monorepo. ADR-0039 step 6 (remove the monorepo copy) is the fix; until then every shell change can silently ship from the wrong tree, or neither.
Harness failures that impersonate OS failures (#272)Today’s ab-sysupdate red cost a full re-run to prove innocent. A gate whose own infrastructure can fail invisibly taxes every future red with “is it us?”.
Issues rot faster than they close#146 sat open for weeks because its checkboxes named a renamed directory. The report you are reading exists partly to counter this.
